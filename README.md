# HW1 — регрессия с инференсом: выводы

Решение: `HW1_Regression_with_inference_base_solution.ipynb`.
Инференс: `app.py`, `hw1_model.pickle`, `requirements.txt`, `runtime.txt`.

## 1. Что было сделано

**EDA и предобработка.** Загружены `cars_train.csv` (6999×13) и `cars_test.csv` (1000×13). Найдены пропуски в `mileage`, `engine`, `max_power`, `torque`, `seats`; явные дубликаты (985) и дубликаты по признаковому описанию (1159 лишних строк) удалены → train стал 5840×13. Из строковых признаков `mileage`, `engine`, `max_power` извлечены числа, `torque` удалён, пропуски заполнены медианами, посчитанными **только по train**, `engine` и `seats` приведены к `int`. Построены pairplot, correlation heatmap, гистограммы цены и boxplot цены по типу топлива; дашборд `ydata-profiling` сохранён в HTML.

**Модели.** Обучены: линейная регрессия на 6 вещественных признаках (сырые и стандартизованные данные), Lasso с `alpha=1`, Lasso и ElasticNet с гиперпараметрами, подобранными 10-fold GridSearchCV, затем Ridge на one-hot-кодированных категориальных признаках (включая `seats`) с перебором `alpha`. Качество оценивалось по $R^2$, MSE и кастомной бизнес-метрике (доля прогнозов с относительной ошибкой ≤10%).

## 2. Ключевые выводы

- **Наибольший прирост дало добавление категориальных признаков**: R² на тесте вырос с 0.594 до 0.626, MSE снизилась. One-hot с `drop_first` убирает мультиколлинеарность; кодировщик обязательно обучается на train, иначе в test (где нет `seats=2`) столбцы дамми съезжают.
- Стандартизация **не меняет** метрики МНК (это обратимая замена признаков), но позволяет сравнивать коэффициенты: самый важный признак — `max_power` (β≈3.2e5).
- `Lasso` с дефолтным `alpha=1` почти не отличается от МНК: штраф на 5 порядков меньше SSE. При `alpha≈2.5e4` (41×10=410 обученных моделей в grid) обнулились `mileage`, `engine`, `seats`, но R² на тесте снизился — смещение перевесило выигрыш в дисперсии.
- Лучшая модель по $R^2$ — Ridge с `alpha=1`, лучшая по бизнес-метрике — Ridge с `alpha≈562` (25.3% попаданий в ±10%). Для бизнеса выбираем вторую: $R^2$/MSE доминируются редкими дорогими авто, а бизнес-метрика считает попадания в порог.

## 3. Что не удалось / ограничения

- Не удалось поднять $R^2$ регуляризацией: у модели только 6–10 признаков, а цены имеют тяжёлый правый хвост; остальная дисперсия — шум и неучтённые факторы. Тестовая MSE вдвое больше тренировочной из-за выбросов в test.
- Не использован столбец `name` (по условию задания): выделение марки/модели могло бы добавить сигнал.
- Не опробовано логарифмирование целевой переменной, хотя гистограммы показывают правостороннюю асимметрию цены.
- Streamlit Community Cloud: приложение **не опубликовано**, так как нет доступа к аккаунту; подготовлены файлы и инструкция ниже.

## 4. Инференс и приложение

`hw1_model.pickle` содержит:
- `pipeline`: `ColumnTransformer` (passthrough числовых + `OneHotEncoder(drop="first", handle_unknown="ignore")` для категорий) → `StandardScaler` → `Ridge(alpha=562.34)`;
- `medians`, `feature_order`, `best_params`, `cv_r2`, `metrics`;
- очищенную обучающую выборку `train_data` для графиков EDA.

Проверка: предсказания пайплайна совпадают с ноутбуком (R² test = 0.6132, бизнес-метрика = 0.253). Для медианных значений признаков модель возвращает ≈859 878.

`app.py` (4 вкладки):
1. **Предсказание** — ввод признаков в полях или загрузка CSV (поддерживаются как «сырые» колонки с единицами измерения, так и очищенные); вывод цены и коридора ±10%, для CSV — таблица и скачивание результата.
2. **EDA** — гистограммы цены (исходная и log), boxplot по топливу, scatter «мощность — цена», heatmap корреляций.
3. **Веса модели** — топ-20 коэффициентов по модулю и полная таблица; подпись, что признаки стандартизованы.
4. **О модели** — метрики, гиперпараметры, список признаков.

### Оценка приложения

Удобство: все разделы на одной странице с вкладками, ввод одного объекта занимает секунды, CSV-режим закрывает сценарий пакетного скоринга. Хорошо визуализируются асимметрия цены, влияние типа топлива и мощности, а также знак и величина весов модели. Ограничения: коэффициенты дамми сложнее интерпретировать», нет доверительных интервалов и контроля дрейфа данных; неизвестные категории кодируются нулями; приложение зависит от актуальности `pickle`. ## 5. Запуск и публикация

Локально из корня репозитория:

```bash
pip install -r requirements.txt
streamlit run app.py
```

Публикация на Streamlit Community Cloud:

1. Зафиксировать файлы `app.py`, `hw1_model.pickle`, `requirements.txt`, `runtime.txt` в GitHub-репозитории (pickle ≈0.5 МБ, Git LFS не нужен).
2. Зайти на https://streamlit.io/cloud через GitHub, нажать **New app**.
3. Указать репозиторий, ветку `main` и main file path `app.py`.
4. Нажать **Deploy**; Streamlit прочитает `requirements.txt` и `runtime.txt` (Python 3.12).
5. После деплоя открыть ссылку и проверить вкладки «Предсказание», «EDA», «Веса модели».

Ссылку на опубликованное приложение следует добавить сюда после деплоя.
